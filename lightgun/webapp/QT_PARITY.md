# Qt App -> Web App correspondence

Every slot and function of the Qt App (`OpenFIRE-App/src`) and where the web app implements it.
Tests: `tests/*.test.js` (Node) and `tests/browser-e2e.js` (browser, simulated lightgun).

## Intentional differences

- Calibration posture reminder, in both Apps: two centred English/Italian lines above the bottom instructions stay visible through final verification, including refused-shot warnings. Existing texts, targets, progress and IR panel keep their sizes and positions; only the reminder moves up when the verification instructions or refusal box need more space. On small screens (800×600) a long refusal box moves down, within the screen, so that the reminder stays clear of the values list (WebApp `_drawCalibration`, Qt `CaliIrRefresh`). In Qt its bitmap is generated once per window, with no new timer.
- Linux checks of the Qt App (user not in `dialout`, running as root): not applicable to a browser.
- File dialogs: the browser file chooser and download replace "Open New Layout" / "Save New Layout"; a download cannot be cancelled, so "Canceled custom layout save operation." does not exist.
- Device list: Web Serial only lists ports the user allowed, so the Qt device selector is replaced by a `Connect` button that opens the browser's port chooser.
- Menu bar: View, Help and About with the Qt entries; "Board Previews" and "Emitter Alignment" (also in Help) are added as buttons, with the language and theme selectors. "OpenFIRE on the Web" (a disabled placeholder in the Qt menu) is not shown; About opens directly (the Qt About menu has only "About OpenFIRE...").
- Emitter Alignment, in both Apps, is a fullscreen placement planner: screen size/format, camera, entered converter factor and playing distance drive the Square markers and centimetre measurements; one play profile (side movements, gun roll up to 15°) replaces the former movement-space choice. On opening it selects the first green distance (or 10 m if none fits). Later setup and layout changes preserve the chosen distance; **Set ideal minimum distance**, below its slider, recomputes it on request, including the 10 m cap and limited-coverage warning. The cached progression prioritises a geometric precision estimate, accepts only improvements at both sensor and camera-output resolution scales, and shows the first useful placement below the usable range. Diamond remains at the edge centres. **Force legacy placement** below the distance group locks and dims all setup controls, uses fixed Square geometry or Diamond edge centres, and replaces optical advice with a legacy notice. Toggling it off restores the preserved setup and distance, including individual lens restrictions. It runs offline and does not change device settings. The Qt App has the same window (`AppAlignmentWindow`, from Help > Open IR Emitter Alignment Assistant), with the same texts in English and Italian and the calculation ported to C++ (`appemitterlayout.cpp`); like the WebApp it does not open while a calibration, IR test or lens refinement is in progress. The former Qt alignment view (`AppCaliWindow::modeAlignment`) is no longer opened.
- Turning custom pins off/on or choosing an alternative preset keeps the rumble/solenoid toggles when their pins are mapped again, in both Apps. Importing a layout gives rumble and solenoid back their saved values, exactly like the Qt App.
- Gun Settings → Solenoid, in both Apps: **Solenoid Autofire Wait Time** goes up to 9999 ms like the other timings and **Solenoid ON Length** up to 500 ms (Qt: `maximum` of the spin boxes in `appmainwindow.ui`); 99 ms is too short for the return stroke of heavy arcade solenoids. The firmware stores both as `uint32` and uses them as they are, so a value above 99 is no longer lowered on load and written back on the next save.
- Changing the output type of a button selects the first output of the new list, in both Apps; going back to the saved type gives back the saved output.
- Renaming a profile starts from the current name (selected, typing replaces it); the Qt box starts empty. Characters outside Latin-1 are refused like in the product name.
- After Clear Save Memory the confirmation is shown as soon as the command is delivered: the firmware restarts without answering.
- Fullscreen screens: the browser owns fullscreen mode, so leaving it (ESC, F11, browser gesture) closes the screen like ESC; the page behind cannot be used meanwhile. If the browser refuses fullscreen mode, a button asks for it again.
- Leaving IR test mode without the board confirming it is reported as an unconfirmed operation (reconnect), instead of leaving the tabs locked.
- IR test blob view (`sTestBlobs`): the area and brightness under each circle are shown with `?irdebug` in the address; the Qt App uses the `--irdebug` command-line argument.
- Calibration IR view, in both Apps: with firmware that sends the IR emitters (the App asks for it with `caliFlagIrView`, fourth byte of `sCaliStart`; older firmware ignores it), the crosshair changes colour with the weakest emitter (red when one is missing, otherwise a continuous scale from red through orange to full green with its brightness) and a square, rounded panel at the bottom right, labelled "IR LEDs" at its centre in the system font, shows each emitter in its layout, in the same scale from its own brightness. A thin dashed outer ring highlights each target: ten 21-degree segments with 15-degree gaps, one clockwise turn in 8 seconds, radius 48/39 of the original circle, line width 2.1 at unit crosshair scale (the original circle is 2.4), in the same colour actually loaded for the crosshair. It has no fill, pulsing or arrival ripples; the original crosshair geometry stays unchanged. The coloured ring is absent during the shot flash and verification, and stationary in the browser with reduced motion (Qt has no such setting). Both animate at about 30 frames/s; Qt builds both ring paths only once. The firmware refuses every target shot while an emitter is missing (`sCaliIrWarning`), and the window explains why; a weak emitter (orange crosshair) is accepted. The firmware also refuses a target shot, with or without the IR view, while the gun is rotated around the barrel beyond half the angle that would swap the emitters, about 15 degrees on a 16:9 screen (bit 2 of `sCaliIrWarning`): both Apps explain it, after the missing-emitter lines when both bits are set. Each refusal also says how to get past it (WebApp `_caliIrWarningText`, Qt `CaliIrWarningLines`): with an emitter missing, "If an emitter is out of view, step back a little", which at the edges and corners of the standard calibration adds "if you cannot, exit and tick Tolerant calibration"; at the edges of the tolerant calibration a rotation, aim or not-updated refusal adds "If it persists, aim towards the centre for a moment, then back at the target."
- Calibration progress, in both Apps: both Apps ask for the four corners too (`caliFlagCorners`, fourth byte of `sCaliStart`), so with firmware that uses them the dots above the stage title and the targets are ten: centre, top, bottom, left, right, top-right, bottom-right, bottom-left, top-left and final centre. Older firmware ignores the flag: the Apps go back to six (centre, top, bottom, left, right and final centre) when the final centre follows the right edge. After each shot flash the target glides to the next point in 250 ms (smoothstep, straight line; no glide into verification, nor in the browser with reduced motion: Qt has no such setting). Completed dots are filled grey, the current one is green independently of IR quality, future dots are outlined grey; all are filled grey during verification. The dots have no shot animation. Only a consecutive forward stage update starts a solid stationary white outer ring (120 ms: 40 ms fully white, then an 80 ms fade; no fade in the browser with reduced motion). The original crosshair stays at that position until the flash finishes, then moves to the latest target or verification cursor. Data, stage, progress, captions and value updates remain immediate. Duplicate updates do not restart the flash; resets, skipped stages and refused shots do not start one. Rapid consecutive acquisitions replace rather than queue the flash, keeping the visible crosshair still and remembering the latest position. The final centre uses the same flash before following the verification cursor; cursor events during it are retained. This acknowledges acquisition, not saving to flash; no calibration command, value or protocol is changed. Captions and numeric labels are translated in English/Italian, including accented Italian bitmap text.
- Tolerant calibration, in both Apps: a check box under the "Calibrate Profile" buttons (Qt `caliTolerantBox`), off at every start, adds `caliFlagTolerant` (bit 3 of the fourth byte of `sCaliStart`, always with `caliFlagCorners`). The firmware then needs two emitters at the edge shots and none at the corners, all four at the two centre shots; it refuses a shot at an edge fired before reaching the target (bit 3 of `sCaliIrWarning`, "aim at the target"; a corner shot that fails the aim or roll check is taken without measuring that corner, since with two or three emitters the tracker can assign them to the wrong vertices until it sees all four) and, when the refinement fails, does not accept the trigger in verification (bit 4 of `sCaliIrWarning`); a shot at an edge with the emitters seen but the position not updated in that frame is refused with bit 5 (at a corner it is accepted and the corner is not measured): the window then asks to repeat the calibration with Button A or B. At a grey corner the reason of an earlier refusal is removed once it has been shown for one second (WebApp `CALI_IR_WARNING_MIN_TIME` in `_drawCalibration`, Qt in `CaliIrRefresh`), since the next shot is taken without checks. The firmware never uses the tolerant calibration without an App.
- Legends, in both Apps: the calibration window shows a static legend at the bottom left, from the first target through verification (signal intensity scale, IR point size, not-detected symbol and two notes); the IR test window shows its own legend at the bottom left (layouts with the applied one underlined, intensity and size samples, not-detected and reconstructed marks, aim, emitter centre and joining lines). Both are drawn once in the system font, below the live points, and are rebuilt only when the language or, in the IR test, the applied layout changes (WebApp `_createCaliLegend` / `_createIRTestLegend`, Qt `CaliIrDrawLegend` / `IrTestDrawLegend`, `SetIrTestDiamond`). In the IR test the aim is drawn as a crosshair (circle plus ticks) instead of a plain circle.
- Save and Send Settings pulses while there are unsaved changes, in both Apps (in the browser a steady ring when the system reduces animations; Qt has no such setting).
- The Boards Previewer and the colour chooser are page windows; the previewer, like the Qt window, stays open while the main window is used.
- About credits the original OpenFIRE App by That One Seong, names Alessandro Satanassi as the author of this App (based on the original App, extended for OpenFIRE ESP32) and links his Ko-fi, followed by the GPL-3.0 and copyright notices; the Qt version line is not shown.
- Colours of the GPIO labels: exact Qt colours in the dark theme, slightly darker ones in the light theme for contrast.
- The rumble and solenoid tests follow the unsaved toggles like the Qt App; the firmware ignores the rumble test while the saved map has no rumble pin.
- Gun Settings → CAMERA Model, in both Apps: **Parallax correction (camera below the sight)** (`CamParallax`, percent of the vertical LED distance, shown without a unit, 0..25, default 0), locked by **Unlock CAMERA Modification** like the model. The firmware uses it only while playing, with the LED area saved by the last calibration of the profile (`CaliArea`, kept in the firmware like the LED shape).
- Gun Settings → Input / Output, in both Apps: **Wireless power saving, standby after** (`StandbyMinutes`), a list with the values of `standbyMinutesChoices` (Disabled = 0, 5, 15, 30, 60 minutes, default `standbyMinutesDefault` = 15). A saved value not in the list is shown, and used by the firmware, as the default. Only the wireless battery mode uses it.
- Lens refinement (Settings, camera section, `Refine lens...`), in both Apps: a fullscreen IR test with `irTestFlagLens` (second byte of `sIRTest`); the firmware answers with `sLensInfo` and `sLensSample`, older firmware ignores the flag and the window says it is not supported. The values are kept in `CamLensK1`, `CamLensK2` and `CamLensFocal` (`lensValueUnset` = record of the camera); saving another camera model resets them in the firmware, whichever App saves. Details in `lib/OpenFIREPosition/OpenFIRE-Lens-Correction-EN-IT.md`, section 12.
- Gun Tests → Switch, in both Apps: a row with the rumble, solenoid and autofire switches under the buttons (on, off, dashed without a pin), with the temperature beside it under the analog stick. The docked firmware sends `sSwitchStateUpd` (byte 0 switches read, byte 1 switches enabled; bit 0 rumble, 1 solenoid, 2 autofire) as soon as one changes and twice a second, read like in Run mode, normally closed setting included. With older firmware the mapped switches stay dashed and their tooltip asks for a firmware update.

## Added for the browser

- Lightgun page: automatic reconnection; a page in a background tab does not take the gun from the page in use; after three takeovers in 30 seconds a page stops and offers `Reconnect` (two open pages would otherwise take the gun from each other forever).
- Unsaved edits of a lost link (calibrations kept only in the board RAM included) are offered back when the same gun docks again; the browser asks before leaving a page with unsaved edits.
- Questions left open when the link is lost (Save, Clear Save Memory, rename, colours, layout import, IR test warning) close by themselves and do nothing.
- Links of the Qt texts open in a new tab, so the page keeps its board.
